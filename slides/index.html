The problem

A farmer makes dozens of decisions a season, with nobody to ask.

Advice is scattered

Pesticide shop, YouTube, neighbours, the extension officer who visits twice a year. Nobody agrees.

Risk stays invisible

Heat, frost, untimely rain and disease pressure are only noticed after the damage is done.

Diagnosis costs a trip

A sick leaf means a photo, a journey and a wait — so most farmers guess, or over-spray.

English-only tools exclude

The people who farm are least served by apps written for a different user in a different language.

The information exists. It just never reaches the farmer in a form they can use, in a language they read.

Design decision

Urdu isn't a translation layer.
It's the product.

Real RTL, not flipped

Logical spacing and alignment throughout, so layouts mirror correctly instead of breaking.

Typography that stays readable

Noto Sans Urdu for UI at 12–16 px; no root font scaling, so nothing overflows.

AI follows the UI

Diagnosis and chat answer in the selected language — verified on the server.

Every key exists in both dictionaries, and a test fails the build if English and Urdu drift apart.

Kissan AI
Engineering choices

AI where it helps. Deterministic code where it matters.

1

Rules, not guesses

Growth stage, risk scoring, irrigation and yield are plain TypeScript engines. Same input, same answer — explainable, testable, free.

2

The model only does language

Gemini reads the photo and writes the sentence. It never decides the risk score or the watering amount.

3

Language is enforced server-side

Prompt + schema hints + a script check on every field, with a repair pass if the model drifts back to English.

4

Degrade, don't fail

Rate-limited model → second provider. Weather source down → cached view. Missing data → the UI says so.
